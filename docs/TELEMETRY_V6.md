# ЦУП Альтаир v6 — протокол телеметрии

Версия приложения: **0.6.0**  
Радиочастота основного профиля: **435.000 МГц**

## 1. Основной пакет

Пакет передаётся как обычная ASCII-строка без префикса `$TM`:

```text
02,00001,00015,3.00,4.20,1,33
```

Все поля имеют фиксированную длину и разделяются запятыми.

| № | Поле | Длина | Пример | Смысл |
|---:|---|---:|---|---|
| 1 | ID | 2 | `02` | номер команды / спутника |
| 2 | PACKET | 5 | `00001` | порядковый номер пакета |
| 3 | UPTIME | 5 | `00015` | время после запуска, с |
| 4 | PANEL_POWER | 4 | `3.00` | мощность солнечных панелей, Вт |
| 5 | VOLT | 4 | `4.20` | напряжение аккумулятора, В |
| 6 | MODE | 1 | `1` | 1 — штатный, 0 — аварийный |
| 7 | CHECKSUM | 2 | `33` | XOR, HEX |

### Важное уточнение по длине

При указанных длинах полей итоговая строка имеет **29 символов**, а не 23:

```text
2 + 1 + 5 + 1 + 5 + 1 + 4 + 1 + 4 + 1 + 1 + 1 + 2 = 29
```

Здесь шесть единиц — это шесть запятых.

## 2. Ограничения fixed-width формата

Поле `PANEL_POWER` длиной 4 символа и поле `VOLT` длиной 4 символа в виде `X.XX` допускают диапазон `0.00...9.99`. Если в будущем потребуется значение `10.00` и выше, формат пакета придётся расширить.

`PACKET` и `UPTIME` имеют 5 цифр и поэтому работают в диапазоне `00000...99999`. После достижения `99999` бортовая логика должна либо начать счёт заново, либо перейти на новый формат протокола.

## 3. Аварийный режим

В окончательной бортовой программе:

```cpp
mode = (batteryVoltage < 2.00f) ? 0 : 1;
```

То есть при напряжении ниже 2.00 В передаётся `MODE=0`.

Статический тестовый пакет содержит `VOLT=4.20`, поэтому в нём передаётся `MODE=1`.

## 4. Контрольная сумма XOR

XOR вычисляется по ASCII-кодам всей строки до двух символов контрольной суммы. **Последняя разделительная запятая входит в XOR.**

Для примера вычисляется XOR строки:

```text
02,00001,00015,3.00,4.20,1,
```

Результат:

```text
0x33
```

Поэтому итоговый пакет:

```text
02,00001,00015,3.00,4.20,1,33
```

ESP32-шлюз повторно вычисляет XOR. При несовпадении пакет не передаётся в основную телеметрию и выдаётся ошибка `TELEMETRY_XOR`.

## 5. Радиопрофиль CC1101

Передатчик STM32 и наземный ESP32-шлюз используют одинаковые параметры:

```text
Frequency:       435.000 MHz
Bit rate:        4.8 kbps
Modulation:      2-FSK
Deviation:       5 kHz
RX bandwidth:    58 kHz
TX power:        5 dBm
Preamble:        16 bits
```

После приёма корректного пакета ESP32 формирует для ЦУПа внутреннюю строку:

```text
$TEL,ID=02,PACKET=00001,UPTIME=00015,PANEL_POWER=3.00,VOLT=4.20,MODE=1,CHECKSUM=33,CHECKSUM_OK=1,RSSI=-76.0,SNR=16.0,LQI=103
```

`RSSI`, `LQI` и оценочный `SNR` относятся к наземному приёму и поэтому в 29-символьный бортовой пакет не входят.

## 6. STM32-передатчик

Файл:

```text
firmware/transmitter_stm32_v6/Transmit_v6_static/Transmit_v6_static.ino
```

Он использует то же назначение управляющих выводов CC1101, что и ранее работавший пользовательский `Transmit_original.ino`:

```text
CS   = PA2
GDO0 = PA0
GDO2 = PA1
```

Скетч один раз в секунду передаёт одну и ту же статическую строку. Это специально сделано для первого стендового теста всей цепочки STM32 → CC1101 → эфир → CC1101 → ESP32 → ЦУП.

## 7. Отображение в ЦУП Альтаир

Основные карточки v6:

- ID;
- номер пакета;
- uptime;
- мощность солнечных панелей;
- напряжение аккумулятора;
- режим работы;
- XOR;
- RSSI;
- SNR.

Поле раскрытия антенны из v5 сохранено как дополнительное, но **не входит в минимальный 29-символьный пакет v6**. Для его передачи нужен расширенный пакет или отдельная телеметрическая команда.

Графики строятся для `VOLT`, `PANEL_POWER`, `RSSI` и `SNR`.
