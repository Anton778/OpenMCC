# ЦУП Альтаир

**ЦУП Альтаир — Центр управления полётами** — настольное приложение наземной станции для учебных МКА/CubeSat.

**Релиз v5 / 0.5.0 подготовлен для Технопрома 2026: «Миссия на Луну».**

Приложение работает локально и после установки не требует Python, Arduino IDE или доступа в интернет. Основная архитектура наземной станции:

```text
                         ЦУП Альтаир
                              │
                         USB / Serial
                              │
                       ESP32-WROOM-32
                       радиошлюз ЦУПа
                              │
                    ┌─────────┴─────────┐
                    │                   │
                 CC1101              E32-433T30D
                    │                   │
                    └────── радиоканал ─┘
                              │
                             МКА

Отдельный USB-канал:
ЦУП Альтаир → Arduino Uno → CNC Shield V3 → NEMA17 AZ / EL
```

## Главное в v5

Интерфейс переименован и перестроен под демонстрацию на Технопроме. На первом экране отображаются:

- **ID спутника**;
- **напряжение аккумулятора**, В;
- **мощность, вырабатываемая солнечными панелями**, Вт;
- **счётчик отправленных аппаратом пакетов**;
- **время работы после запуска**, с;
- **состояние раскрытия рулеточной антенны**: `1` — раскрыта, `0` — сложена;
- **температура**, °C;
- **RSSI**, dBm;
- **SNR**, dB.

Измерение тока полностью удалено из интерфейса, графиков и демонстрационных данных v5.

Сразу под карточками телеметрии расположены графики `VOLT`, `PANEL_POWER`, `TEMP`, `RSSI`, `SNR`. После них идут командный канал, настройка радиотракта, встроенная прошивка ESP32, поворотное устройство и остальные инженерные панели.

## Формат телеметрии Технопром 2026

Для текущего релиза рекомендуется именованный формат `KEY=VALUE`. Он позволяет добавлять новые параметры без изменения порядка уже существующих полей:

```text
$TM,ID=<ID>,PACKET=<N>,UPTIME=<s>,VOLT=<V>,PANEL_POWER=<W>,TEMP=<°C>,ANTENNA=<0|1>
```

Пример:

```text
$TM,ID=04,PACKET=427,UPTIME=1864,VOLT=4.12,PANEL_POWER=1.850,TEMP=24.4,ANTENNA=1
```

`ANTENNA=1` означает, что бортовая рулеточная антенна раскрыта. `ANTENNA=0` означает, что антенна сложена.

Наземный CC1101-шлюз после приёма добавляет параметры качества радиолинии и передаёт в приложение нормализованную строку:

```text
$TEL,ID=04,PACKET=427,UPTIME=1864,VOLT=4.12,PANEL_POWER=1.850,TEMP=24.4,ANTENNA=1,RSSI=-76.5,SNR=18.2,LQI=103
```

Парсер также принимает позиционный вариант:

```text
$TM,<ID>,<PACKET>,<UPTIME>,<VOLT>,<PANEL_POWER>,<TEMP>,<ANTENNA>
```

Например:

```text
$TM,04,427,1864,4.12,1.850,24.4,1
```

Для работы через текущий ESP32-шлюз предпочтителен именованный пакет `$TM,KEY=VALUE,...`: шлюз передаёт все такие поля без изменения и добавляет наземные RSSI/SNR/LQI.

Парсер сохраняет совместимость с более ранним IntroSat-пакетом, где присутствовали `LIGHT`, `MODE` и `ERRORS`. Значение `LIGHT` не преобразуется автоматически в мощность панелей: для такого пересчёта требуется физическая калибровка конкретного датчика и солнечной панели.

## Совместимость с загруженным `Transmit.ino`

Исходный передатчик, использованный при подготовке v5, содержит:

```cpp
radio.begin(434.00f);
radio.setOutputPower(5);
```

Поэтому профиль **«Технопром 2026»** в интерфейсе CC1101 установлен на:

```text
Частота          434.000 МГц
Скорость         4.8 kbps
Модуляция        2-FSK
Девиация         5 кГц
Полоса RX        58 кГц
Мощность TX      5 dBm
```

В комментариях исходного скетча встречается `433.52 МГц` и `10 dBm`, но фактические вызовы программы задают **434.00 МГц** и **5 dBm**. При настройке приёмника используются именно фактические параметры кода.

Текущая версия загруженного передатчика пока отправляет тестовую строку:

```text
hth htbdr hsh tnhera h5trhga g5h53ed!
```

Поэтому такая версия передатчика ещё не может заполнить карточки ID/напряжения/мощности/состояния антенны. Радиошлюз v5 всё равно примет эту строку и выведет её в журнал как `RF_RAW` вместе с RSSI, оценкой SNR и LQI — это позволяет проверить сам радиоканал.

Для перехода к полной телеметрии в репозитории добавлен пример:

```text
examples/technoprom_2026_transmitter/Transmit_v5.ino
```

В нём уже формируется именованный пакет `$TM,...`; функции чтения аккумулятора, мощности панелей, температуры и состояния раскрытия антенны оставлены отдельными точками для подключения реальных датчиков/логики.

## RSSI и SNR для CC1101

`RSSI` считывается непосредственно из CC1101 через RadioLib.

У CC1101 нет отдельного готового регистра «SNR пакета», поэтому в v5 **SNR является наземной диагностической оценкой**. Радиошлюз отслеживает уровень RSSI свободного канала как оценку шумового фона и рассчитывает:

```text
SNR_est ≈ RSSI_packet − RSSI_noise_floor
```

Это удобно для визуальной оценки качества канала на стенде, но не следует воспринимать это значение как лабораторное измерение отношения сигнал/шум без дополнительной калибровки.

## Радиошлюз ESP32

Проект:

```text
firmware/radio_gateway_esp32/
```

Версия шлюза v5: **0.2.0**.

Поддерживаются:

- CC1101 по SPI;
- E32-433T30D по UART;
- настройка частоты, мощности, скорости и режимов из интерфейса;
- приём телеметрии и передача команд аппарату;
- RSSI/LQI и оценка SNR для CC1101;
- хранение последней RF-конфигурации в NVS ESP32.

В v5 начальные параметры CC1101 совпадают с `Transmit.ino`: 434.000 МГц / 4.8 kbps / 2-FSK / 58 кГц / 5 dBm.

## Прошивка ESP32 прямо из программы

Windows-приложение содержит готовые бинарные образы радиошлюза. В панели **«Прошивка ESP32»** можно:

1. подключить ESP32-WROOM-32 по USB;
2. выбрать последовательный порт;
3. записать bootloader, таблицу разделов, `boot_app0` и приложение;
4. проверить MD5 каждой записанной области;
5. перезагрузить ESP32;
6. подключить её как радиошлюз ЦУПа.

Используется Espressif `esptool-js`. Полное `erase-all` по умолчанию не выполняется.

## Поворотное устройство

Прошивка Arduino Uno:

```text
firmware/rotator_arduino_uno/OpenMCC_Rotator_Uno/OpenMCC_Rotator_Uno.ino
```

Она совместима с панелью AZ/EL и командами:

```text
$ROT,SET,AZ=...,EL=...
$ROT,STOP
$ROT,HOME
$ROT,PARK
$ROT,STATUS
```

До окончательной сборки механики можно использовать встроенный симулятор. Перед аппаратной эксплуатацией требуется определить реальное передаточное отношение и откалибровать шаги на градус.

## Команды аппарату

ЦУП содержит готовые примеры команд: `PING`, `GATEWAY_INFO`, `RADIO_STATUS`, `START`, `STOP`, `STATUS`, `POWER`, `PANEL_STATUS`, а также поле произвольной команды.

Команды, не относящиеся к самому ESP32-шлюзу, передаются им в радиоканал в виде `$CMD,...`. Выполнение конкретной команды зависит от бортовой прошивки МКА.

## Windows-релиз

Полный установщик v5:

```text
CUP-Altair-Setup-0.5.0.exe
```

После установки создаётся ярлык **«ЦУП Альтаир»**. Python, Node.js и Arduino IDE конечному оператору не требуются.

## Что требует аппаратной проверки

Программная сборка не заменяет стендовые испытания. Для полного подтверждения v5 требуется физически проверить:

- приём реального CC1101-передатчика на 434.000 МГц;
- соответствие пакетного режима и синхронизации двух CC1101;
- фактическое формирование `ANTENNA=0/1` по реальному датчику/механизму раскрытия;
- реальные показания RSSI и оценку SNR;
- встроенную прошивку на конкретной ESP32-WROOM-32;
- E32-433T30D, если будет выбран этот вариант;
- механику и калибровку поворотки.
