# OpenMCC — техническое руководство пользователя

Версия документа: **0.2**  
Назначение: зафиксировать текущее состояние проекта, порядок запуска, назначение панелей, аппаратную архитектуру и список незавершённых работ.

---

## 1. Назначение системы

OpenMCC — локальный веб-интерфейс учебного центра управления полётами. Он должен объединить в одном окне:

- приём телеметрии МКА;
- отправку команд управления;
- отображение параметров в числовом и графическом виде;
- журналирование событий;
- визуализацию ориентации аппарата;
- управление двухосевой антенной повороткой;
- в дальнейшем — расчёт орбиты, TLE/SGP4 и автоматическое сопровождение;
- в дальнейшем — двусторонний радиоканал через ESP32-WROOM-32 и CC1101 либо E32-433T30D.

OpenMCC рассчитан на офлайн-работу на одном компьютере. Интернет для штатной работы интерфейса не требуется.

---

## 2. Что требуется для запуска

Минимально:

- ПК с Windows;
- Chrome или Edge с поддержкой Web Serial API;
- Python 3 для простого локального HTTP-сервера;
- папка проекта OpenMCC.

Для теста телеметрии дополнительно:

- Arduino Uno или Nano;
- USB-кабель;
- прошивка `examples/arduino_avr_demo/OpenMCC_Arduino_AVR/OpenMCC_Arduino_AVR.ino`.

Для будущей реальной наземной станции:

- ESP32-WROOM-32 — радиошлюз ЦУПа;
- CC1101 **или** E32-433T30D — радиомодуль;
- спиральная антенна осевого излучения;
- SatNOGS Rotator v3;
- отдельная Arduino Uno для поворотки;
- CNC Shield V3;
- два NEMA17;
- драйверы шаговых двигателей;
- концевые выключатели;
- отдельное питание двигателей и, при необходимости, мощного радиомодуля.

## 3. Запуск OpenMCC

### 3.1. Самый простой способ

Дважды щёлкнуть:

```text
start_openmcc.bat
```

Скрипт запускает локальный HTTP-сервер и открывает браузер.

### 3.2. Запуск вручную

Открыть командную строку в папке OpenMCC и выполнить:

```bash
py -m http.server 8000
```

Если команда `py` отсутствует:

```bash
python -m http.server 8000
```

Затем открыть:

```text
http://localhost:8000/
```

### 3.3. Почему нельзя просто открыть index.html

Для Web Serial API и ES-модулей Three.js требуется корректный контекст страницы. Поэтому рекомендуется `localhost`, а не `file:///.../index.html`.

---

## 4. Главное USB-соединение

Панель **«Соединение с устройством»** управляет основным Web Serial-портом.

Сейчас этот порт можно использовать непосредственно с Arduino/STM32/ESP32. В конечной архитектуре он должен соединять браузер с **ESP32-WROOM-32 — радиошлюзом ЦУПа**.

Порядок работы:

1. Подключить плату к ПК по USB.
2. Выбрать профиль устройства.
3. Для текущих тестовых прошивок выбрать `115200 бод`.
4. Нажать **«Подключить устройство»**.
5. В системном окне браузера выбрать нужный COM-порт.
6. После подключения проверить рост счётчика пакетов.

Web Serial не всегда показывает привычный номер COM в интерфейсе браузера. Это ограничение браузерного API, а не ошибка OpenMCC.

## 5. Формат телеметрии

Базовый текстовый пакет:

```text
$TEL,TEMP=23.50,VOLT=5.01,CURR=182,RSSI=-79,SNR=9.4
```

Парсер также допускает дополнительные поля, в том числе:

```text
ROLL
PITCH
YAW
LAT
LON
ALT
SPEED
POWER
TX
RX
CRC
TIME
```

Сейчас основные карточки интерфейса отображают:

- `TEMP` — температура;
- `VOLT` — напряжение;
- `CURR` — ток;
- `RSSI` — уровень принятого сигнала;
- `SNR` — отношение сигнал/шум.

---

## 6. Команды аппарату

Центр команд использует строки вида:

```text
$CMD,PING
$CMD,INFO
$CMD,START
$CMD,STOP
$CMD,RATE,VALUE=1000
$CMD,LED,VALUE=1
$CMD,LED,VALUE=0
```

Демонстрационная Arduino отвечает сообщениями:

```text
$ACK,...
$ERR,...
$INFO,...
```

После появления реального радиошлюза ESP32 эти же команды должны передаваться далее по радиоканалу, чтобы веб-интерфейс не зависел от типа радиомодуля.

---

## 7. Графики

Модуль `js/charts.js` использует локальную копию Chart.js.

Поддерживаются графики:

- температура;
- напряжение;
- ток;
- RSSI;
- SNR.

Кнопка **«Пауза»** останавливает добавление новых точек на график, но не отключает сам приём телеметрии.  
Кнопка **«Очистить»** сбрасывает накопленный буфер текущего сеанса.

---

## 8. 3D-модель CubeSat

Модуль `js/satellite.js` использует Three.js и OrbitControls.

Текущая модель процедурная и нужна для визуализации работы интерфейса. Она не является точной CAD-моделью реального аппарата.

Поддерживаются:

- вращение камеры мышью;
- сброс вида;
- демонстрационное автовращение;
- подготовленная обработка `ROLL`, `PITCH`, `YAW`.

При появлении реальной ориентационной телеметрии можно управлять положением модели данными аппарата.

## 9. Поворотное устройство антенны

Поворотка использует **отдельный последовательный порт** и отдельную Arduino Uno.

Архитектура:

```text
OpenMCC
   │ USB
Arduino Uno №2
   │
CNC Shield V3
   ├── NEMA17 → AZ
   └── NEMA17 → EL
```

Интерфейс поддерживает команды:

```text
$ROT,SET,AZ=145.00,EL=37.50
$ROT,STOP
$ROT,HOME
$ROT,PARK
$ROT,STATUS
```

Типовые ответы:

```text
$ROT,POS,AZ=144.80,EL=37.30
$ROT,STATE=MOVING
$ROT,STATE=IDLE
$ROT,HOME=OK
$ROT,ERR,...
```

### 9.1. Симулятор

Пока механика SatNOGS v3 не собрана, следует использовать флажок **«Симулятор поворотки»**.

Порядок:

1. Установить флажок.
2. Нажать **«Подключить поворотку»**.
3. Задать AZ и EL.
4. Нажать **«Навести антенну»**.
5. Проверить плавное изменение текущих углов.
6. Проверить «Стоп», «Поиск нуля» и «Парковка».

### 9.2. Реальная механика

Прошивка для Arduino Uno была подготовлена, но реальная механика ещё не собиралась и не проходила калибровку. До установки антенны необходимо отдельно проверить:

- направления обеих осей;
- концевые выключатели;
- ток драйверов;
- микрошаг;
- число шагов на градус;
- программные пределы;
- аварийное отключение.

## 10. Радиоканал

Планируемая архитектура:

```text
OpenMCC
   │ USB
ESP32-WROOM-32
   │
   ├── SPI  → CC1101
   └── UART → E32-433T30D
        │
     радиоканал
        │
       МКА
```

На данный момент окончательный радиомодуль неизвестен — он зависит от закупки.

### 10.1. Если будет CC1101

Планируется:

- SPI;
- работа на 3,3 В;
- использование GDO0/GDO2;
- собственный пакетный драйвер;
- RSSI/LQI;
- CRC и подтверждения на уровне протокола OpenMCC.

### 10.2. Если будет E32-433T30D

Планируется:

- UART;
- линии M0, M1, AUX;
- отдельное питание радиомодуля подходящей мощности;
- общая земля с ESP32;
- прозрачная передача пакетов OpenMCC через радиоканал.

Главный принцип: браузерный интерфейс не должен знать, какой физический радиомодуль установлен.


## 14. Что делать при возвращении к проекту после перерыва

Рекомендуемый порядок:

1. открыть `docs/PROJECT_STATUS.md`;
2. запустить OpenMCC;
3. проверить демонстратор Arduino;
4. проверить графики;
5. проверить симулятор поворотки;
6. только затем продолжать новую функцию.

Следующий приоритет разработки — **радиошлюз ESP32-WROOM-32**, потому что без двустороннего радиоканала ЦУП остаётся только стендом USB-телеметрии.

## 15. Безопасность аппаратной части

- Не подключать и не отключать шаговые двигатели при включённом питании драйверов.
- Перед работой реальной поворотки проверить аппаратные концевики.
- Для реального стенда предусмотреть физическую аварийную остановку.
- Не допускать закручивания коаксиального кабеля при азимутальном вращении.
- E32-433T30D высокой мощности не питать без расчёта источника питания.
- Не передавать в эфир до проверки разрешённых частот, мощности и режима работы для конкретного места эксплуатации.
