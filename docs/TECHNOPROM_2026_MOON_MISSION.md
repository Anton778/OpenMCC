# ЦУП Альтаир v5 — Технопром 2026

## Миссия на Луну

Версия приложения: **0.5.0 / v5**  
Версия ESP32-радиошлюза: **0.2.0**

Этот документ фиксирует рабочую конфигурацию ЦУПа для демонстрации на Технопроме 2026 и отделяет то, что уже реализовано программно, от того, что ещё требует аппаратной проверки.

---

## 1. Назначение

ЦУП Альтаир предназначен для:

- приёма телеметрии учебного МКА;
- отображения состояния аппарата в реальном времени;
- построения графиков;
- настройки наземного радиотракта;
- передачи команд аппарату;
- прошивки ESP32-WROOM-32 радиошлюза непосредственно из приложения;
- ручного управления двухосевой антенной AZ/EL;
- последующего расширения до автоматического сопровождения.

Рабочая архитектура:

```text
                ЦУП Альтаир
                     │
                USB / Serial
                     │
              ESP32-WROOM-32
                 радиошлюз
                     │
                SPI / UART
                     │
             CC1101 или E32
                     │
                    RF
                     │
                    МКА

Отдельно:
ЦУП Альтаир → USB → Arduino Uno → CNC Shield V3 → AZ / EL
```

## 2. Телеметрия v5

На экране отображаются следующие параметры.

| Поле | Назначение | Единица / состояние |
|---|---|---|
| `ID` | идентификатор аппарата | — |
| `VOLT` | напряжение аккумулятора | В |
| `PANEL_POWER` | электрическая мощность солнечных панелей | Вт |
| `PACKET` | номер/счётчик отправленного аппаратом пакета | пакет |
| `UPTIME` | время с момента запуска/включения аппарата | с |
| `ANTENNA` | состояние раскрытия рулеточной антенны | `1` — раскрыта, `0` — сложена |
| `TEMP` | температура | °C |
| `RSSI` | уровень принятого сигнала | dBm |
| `SNR` | оценка отношения сигнал/шум | dB |

Параметр тока в релизе v5 **не используется** и из главного интерфейса удалён.

Карточка `ANTENNA` отображает состояние явно:

```text
1 · РАСКРЫТА
```

или:

```text
0 · СЛОЖЕНА
```

### 2.1. Рекомендуемый пакет миссии

Для Технопрома 2026 рекомендуется именованный формат `KEY=VALUE`:

```text
$TM,ID=<ID>,PACKET=<N>,UPTIME=<s>,VOLT=<V>,PANEL_POWER=<W>,TEMP=<°C>,ANTENNA=<0|1>
```

Пример:

```text
$TM,ID=04,PACKET=427,UPTIME=1864,VOLT=4.12,PANEL_POWER=1.850,TEMP=24.4,ANTENNA=1
```

Именованный формат выбран как основной, потому что новые параметры можно добавлять без изменения порядка существующих полей. Текущий ESP32-шлюз передаёт именованные поля без потерь и добавляет параметры радиолинии.

После приёма CC1101 наземный шлюз передаёт приложению строку вида:

```text
$TEL,ID=04,PACKET=427,UPTIME=1864,VOLT=4.12,PANEL_POWER=1.850,TEMP=24.4,ANTENNA=1,RSSI=-76.5,SNR=18.2,LQI=103
```

### 2.2. Позиционный пакет

Парсер ЦУП Альтаир также принимает:

```text
$TM,<ID>,<PACKET>,<UPTIME>,<VOLT>,<PANEL_POWER>,<TEMP>,<ANTENNA>
```

Пример:

```text
$TM,04,427,1864,4.12,1.850,24.4,1
```

Для рабочего радиоканала через ESP32 рекомендуется использовать именованный вариант из раздела 2.1.

### 2.3. KEY=VALUE через `$TEL`

Также разрешён формат:

```text
$TEL,ID=04,VOLT=4.12,PANEL_POWER=1.850,PACKET=427,UPTIME=1864,TEMP=24.4,ANTENNA=1
```

Порядок именованных параметров значения не имеет.

### 2.4. Совместимость со старым IntroSat-пакетом

Парсер v5 распознаёт более раннюю позиционную структуру:

```text
$TM,ID,PACKET,UPTIME,LIGHT,VOLT,TEMP,MODE,ERRORS*CHECKSUM
```

`LIGHT` сохраняется как отдельное значение. Оно **не переводится автоматически в `PANEL_POWER`**, поскольку для такого перевода нужны характеристики фотодатчика/панели и калибровочная зависимость.

## 3. Анализ загруженного `Transmit.ino`

В репозитории сохранена точная копия исходного файла:

```text
examples/technoprom_2026_transmitter/Transmit_original.ino
```

Ключевые строки фактической программы:

```cpp
int state = radio.begin(434.00f);
radio.setOutputPower(5);
```

Следовательно, приёмник необходимо ориентировать на **434.000 МГц** и **5 dBm** как фактические параметры программы.

В комментариях исходника написано `433.52 МГц` и `10 dBm`; эти комментарии не совпадают с выполняемым кодом и поэтому не используются как источник настройки приёмника.

### 3.1. Профиль RadioLib

Для CC1101 в текущем проекте используется RadioLib `7.7.1`. При вызове:

```cpp
radio.begin(434.00f);
```

стандартный профиль CC1101 соответствует:

```text
Частота:       434.000 МГц
Bit rate:      4.8 kbps
Deviation:     5 кГц
RX bandwidth:  58 кГц
Модуляция:     2-FSK
Preamble:      16 бит
```

Затем передатчик отдельно устанавливает мощность `5 dBm`.

Эти параметры являются стартовым профилем **«Технопром 2026»** в панели радиоканала ЦУП Альтаир.

### 3.2. Что сейчас передаёт исходный скетч

Исходный файл пока передаёт не телеметрию, а тестовую строку:

```text
hth htbdr hsh tnhera h5trhga g5h53ed!
```

Поэтому при работе именно с `Transmit_original.ino` ожидаемое поведение такое:

1. CC1101 радиошлюза принимает пакет;
2. ESP32 получает RSSI и LQI;
3. рассчитывается диагностическая оценка SNR;
4. текст выводится в журнал ЦУПа как `RF_RAW`;
5. карточки ID/VOLT/PANEL_POWER/PACKET/UPTIME/ANTENNA/TEMP не изменяются, потому что этих данных в исходной строке нет.

Это **нормальное диагностическое поведение**, а не ошибка парсера.

## 4. Передатчик для полной проверки v5

В репозиторий добавлен пример:

```text
examples/technoprom_2026_transmitter/Transmit_v5.ino
```

Он сохраняет исходную радиоконфигурацию и формирует именованный пакет:

```text
$TM,ID=04,PACKET=427,UPTIME=1864,VOLT=4.12,PANEL_POWER=1.850,TEMP=24.4,ANTENNA=1
```

В нём предусмотрены функции:

```cpp
readBatteryVoltage()
readPanelPower()
readTemperature()
readAntennaDeployed()
```

Сейчас они возвращают демонстрационные значения и служат точками подключения реальных измерений/состояний. Перед использованием на аппарате их необходимо связать с фактическими АЦП, датчиками и логикой механизма раскрытия.

Важно: `ANTENNA=1` желательно формировать по **подтверждённому фактическому состоянию** механизма, а не только по факту выдачи команды на раскрытие.

## 5. Наземный CC1101

Рекомендуемое подключение к ESP32-WROOM-32:

| CC1101 | ESP32-WROOM-32 | Назначение |
|---|---|---|
| VCC | 3V3 | питание 3,3 В |
| GND | GND | общая земля |
| SCK | GPIO18 | SPI clock |
| SO/MISO | GPIO19 | данные CC1101 → ESP32 |
| SI/MOSI | GPIO23 | данные ESP32 → CC1101 |
| CSn | GPIO21 | Chip Select |
| GDO0 | GPIO4 | событие RX/TX |
| GDO2 | GPIO27 | дополнительный GDO |

На старте релиза v5 в прошивке шлюза установлено:

```text
FREQ=434.000
POWER=5
RATE=4.8
MOD=2FSK
BW=58
CRC=1
CCA=1
```

Эти параметры можно изменить прямо из ЦУП Альтаир.

## 6. RSSI и SNR

### RSSI

`RSSI` поступает непосредственно от CC1101 через RadioLib после приёма пакета.

### SNR

CC1101 не выдаёт готовый числовой SNR пакета как отдельный параметр. Поэтому в релизе v5 используется **оценка SNR на стороне наземного шлюза**:

```text
SNR_est = RSSI_packet − RSSI_noise_floor
```

`RSSI_noise_floor` оценивается по RSSI свободного канала и сглаживается во времени.

Эта величина полезна для:

- визуального сравнения качества приёма;
- наведения антенны;
- учебного стенда;
- сравнения разных положений/антенн.

Она не является заменой калиброванному измерителю SNR.

## 7. Графики

Графики расположены непосредственно под блоком телеметрии и строятся для:

```text
VOLT
PANEL_POWER
TEMP
RSSI
SNR
```

`ID`, `PACKET`, `UPTIME` и `ANTENNA` отображаются как оперативные значения, но отдельные графики для них не создаются.

## 8. Командный канал

Примеры готовых команд:

```text
$CMD,PING
$CMD,GATEWAY_INFO
$CMD,RADIO_STATUS
$CMD,START
$CMD,STOP
$CMD,STATUS
$CMD,POWER
$CMD,PANEL_STATUS
```

`GATEWAY_INFO` и `RADIO_STATUS` обрабатываются наземным ESP32-шлюзом. Остальные команды пересылаются в эфир. Бортовая часть должна отдельно реализовать их выполнение.

## 9. Прошивка радиошлюза

В Windows-приложение входят готовые бинарные образы ESP32. Оператору не нужны Arduino IDE или PlatformIO.

Последовательность:

```text
подключить ESP32-WROOM-32
        ↓
Прошивка ESP32
        ↓
Прошить радиошлюз
        ↓
определение типа чипа
        ↓
запись Flash
        ↓
MD5-проверка
        ↓
hard reset
        ↓
Подключить как шлюз
```

Записываются области:

```text
0x1000   bootloader
0x8000   partition table
0xE000   boot_app0
0x10000  Altair Radio Gateway
```

## 11. Проверка перед Технопромом

Минимальный стендовый тест:

1. Установить `CUP-Altair-Setup-0.5.0.exe`.
2. Прошить ESP32 из панели приложения.
3. Подключить CC1101 к ESP32 по таблице выше.
4. В панели радиоканала применить профиль **«Технопром 2026»**.
5. Включить исходный `Transmit_original.ino`.
6. Убедиться, что в журнале появляется `RF_RAW` с текстом тестового пакета и RSSI/LQI/SNR.
7. Затем загрузить/реализовать `Transmit_v5.ino`.
8. Убедиться, что заполняются все девять карточек телеметрии, включая `ANTENNA`.
9. Изменить тестовое значение `ANTENNA` с `1` на `0` и проверить отображение «РАСКРЫТА/СЛОЖЕНА».
10. Проверить пять графиков.
11. Проверить `RADIO_STATUS`.
12. Проверить передачу безопасной команды по радиоканалу на стенде.
13. Проверить поворотку сначала в симуляторе, затем на механике после калибровки.

---

## 12. Что нельзя считать проверенным только по сборке ПО

Даже при успешной CI-компиляции необходимо отдельно подтвердить на железе:

- чувствительность и устойчивость реального CC1101-модуля;
- пакетную совместимость конкретных модулей передатчика/приёмника;
- качество питания и разводки SPI;
- фактическое определение состояния раскрытия антенны;
- оценку шумового фона/SNR;
- дальность радиолинии;
- работу E32, если он будет применяться;
- физическую поворотку и концевые выключатели.

Только после этих испытаний конкретную аппаратную конфигурацию можно считать полностью принятой.
